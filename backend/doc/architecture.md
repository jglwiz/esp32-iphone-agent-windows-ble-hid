# Backend 架构与运行约定

Backend 为顶层，ESP32 和 AirPlay 为两个核心子模块。FastAPI、管理器、配置、日志和完整任务编排属于 Backend。

## 依赖和并发

- ESP32 的 SerialService 是进程内 actor：通过有界队列接受命令，唯一串口线程执行打开、协议、心跳、重置与关闭。它不读取 AirPlay，也不依赖 FastAPI。
- orchestration.py 串行保留完整控制任务，负责视觉定位、界面等待和截图结果；串口代理只负责提交命令。取消必须完成释放与收尾，不能插入其他输入任务。
- AirPlay frames/routes 只读快照，可以与输入并行。最新快照与操作后新鲜帧有不同契约：前者保留旧帧时间，后者要求满足 settled_at 及年龄限制。
- 校准页面 8893 在 API 事件循环上运行，仍有独立令牌校验，不提供任何串口或通用控制路由。

## 进程和线程

主控、API、取帧为三个 Python 进程；UxPlay 是外部运行时。主控负责启动和复用；API 重启只交接 API 与串口，不重启投屏。主控恢复须核验 PID 创建时间、服务实例、配置路径及认证管理身份。

主要线程：主控事件循环 1；API 事件循环、串口 actor、固定视觉编排线程各 1；取帧 HTTP 事件循环、管道读取线程各 1。当前是 **6 个固定主要线程**，比初始预算多一个有界的同步视觉编排线程。API 框架和图像库还可能产生线程池线程。不会为每个 frame 请求新建线程。

API 进程仅启用一个 worker，不能启用 reload 或同时运行直接串口脚本。用于独立单元测试的校准 Receiver 可创建自己的事件循环线程，正式 API 注入当前事件循环，不使用该回退。

## 端口

| 端口 | 用途 |
|---|---|
| 8892 回环 | 唯一客户端控制、截图及管理 API |
| 8891 回环 | AirPlay 内部快照服务 |
| 8894 回环 | 主控认证管理通道，不是客户端入口 |
| 8893 局域网 | 手机校准令牌页 |

8890 旧 USB 控制服务退役；上线验收与旧代码清理状态以实施记录为准。

## 生命周期与数据

配置只在 Backend 层解析：IPHONE_PROJECT_ROOT 和 IPHONE_RUNTIME_DIR 必须是绝对路径。安装部署显式设置；开发检出仅支持已识别的仓库布局回退。源码与运行数据分离，既有校准资料仍位于 runtime/service/。

设备重置通过 RTS/EN 进行一次脉冲，保留配对和 Flash。请求必须绑定 API 实例、设备 ID 和旧 boot_id；与完整任务、校准和后端重启互斥。先持久保存意图，再执行；结果未知时不重发。新 boot_id 证明设备重启，BLE readiness 单独报告，既有定位证据需要重新验证。

主控的取帧启动任务按 request_id 持久保存。进程已存在则验证身份并复用，错误 owner 明确拒绝。中断恢复先查询现状，不盲目重复启动。

主控失联时 API 保持当前能力，但拒绝后端重启。设备故障不等于 Backend 死亡，日志、画面、状态仍可查询。API 正常交接需留下清理成功证明且进程真正退出；没有证据时主控停止自动替换并报告需处理。
