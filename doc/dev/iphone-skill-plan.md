# iPhone Skill 实施计划

状态：仓库 skill 与使用文档已实施；静态审查完成，实际发现、跨目录调用和设备验收待验证。未创建或替换用户级入口。

## 目标与已确认约定

面向开发者，在本仓库提供一个可随代码维护的 `iphone` skill。用户 clone 后可以在项目中使用，也可以自行复制或链接到用户级 skill 目录，在其他项目中调用同一后端。

- 不提供 skill 安装工具；README 说明目录位置和手动使用方法。
- 仓库维护一份源文件，局部与全局使用同一内容。
- 环境部署与手机操作由同一个 skill 按任务分流；安装 skill 不等于部署后端。
- 复用现有后端及部署工具，不在 skill 中另建串口控制实现或复制后端业务逻辑。
- 本机路径、凭据和运行产物与公共 skill 内容分开管理。

## 当前依据

- [AI 部署流程](../user/deployment.md) 已说明干净 clone 后的依赖、初始化、启动与只读验收，是部署步骤的维护入口。
- [Backend 使用说明](../../backend/doc/usage.md) 是现有服务操作入口。
- [项目约定](../../AGENTS.md) 定义文档布局、实机操作和测试分工。
- 本机已有用户级 `iphone` skill，包含个人项目路径与环境路径。实施时可参考其操作经验，但需要去除机器绑定，不能直接作为公共版本发布。
- Codex 的局部 skill 目录为 `.agents/skills/`，用户级目录为 `~/.agents/skills/`；同名副本不自动合并。参考 [官方 skill 文档](https://learn.chatgpt.com/docs/build-skills)。

## 内容与目录设计

仓库源文件放在 `.agents/skills/iphone/`：

- `SKILL.md`：触发条件、配置解析、部署与操作分流、证据要求，以及按需读取文档的入口。
- `references/actions.md`：动作参数与示例、截图坐标含义、结果解释和当前能力限制。
- `scripts/iphone_client.py`：仅在现有客户端无法满足独立使用时增加薄 HTTP 封装；优先复用现有能力，避免形成两套客户端业务逻辑。

部署步骤继续维护在 `doc/user/deployment.md`，不再创建另一份重复的 `references/deployment.md`。全局使用时通过本机配置定位 clone 后的仓库，再读取该文档。skill 自带资源相对于 skill 目录定位，仓库文档相对于已解析的仓库目录定位，均不能依赖调用方的当前工作目录。

## 验收标准

1. 仓库内存在可发现的 `iphone` skill，源文件受 Git 管理，无需专用 skill 安装工具。
2. 开发者 clone 后可让 AI 根据现有部署入口完成环境准备，并明确报告需要人工处理及尚未验证的部分。
3. 同一 skill 可手动复制或链接为用户级入口，并能从其他工作目录使用后端。
4. 公共内容不含作者个人路径、真实凭据或本机设备配置；实际配置与运行产物不会被 Git 跟踪。
5. 后端控制逻辑保持单一维护来源，skill 参数与当前 API 对应，部署步骤没有重复维护。
6. README 清楚解释复制、链接、分支变化与同名 skill 的影响。
