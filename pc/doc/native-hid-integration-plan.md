# 原生绝对 HID 与自动校准集成计划

日期：2026-10-31。状态：实施中，用户已授权执行本计划。先迁移与隔离测试，再实机验收；默认后端在验收前保持visual_relative。不自动提交Git。

## 目标与已验证范围

保留现有 Python HTTP 客户端及 FastAPI 单串口常驻架构，让 `move_to` / `click_at` 使用原生 BLE Absolute Pointer，消除正常动作中的视觉定位循环。校准时自动采集真实落点，按需修正比例和偏移，日常动作只读取已验证配置。

依据：[自动校准原型](../../task/native-absolute-hid/lab/doc/auto-calibration.md)、[原生 HID 实验](../../task/native-absolute-hid/lab/doc/experiment.md)。两轮均由同一 6.1 Terra / Medium 子代理操作，主代理看图并审计串口和页面事件：

- 原始映射：6个训练样本、5个留出点、5次额外点击通过；无需修正。
- 人为注入(+12,-10)截图像素偏移：自动逆映射使最大轴向误差由约12.13降至1.34像素。该偏差属于测试注入，不是设备本身误差。
- 两轮自动阶段分别约11.50/11.47秒，不包含页面导航。误差来自页面CSS坐标换算，不能宣称硬件亚像素精度。
- 验证仅覆盖Safari专用校准页的一部分屏幕。全屏、边缘、跨应用、重连和长期稳定性尚未完成。主屏九宫格有图标重叠导致的测量不确定，不能当作已通过。

本计划集成的是**原生绝对报告 + 按需自动校准**，不是把“相对移动 + 定期归零”作为默认底层。相对移动仍用于准备页面或明确指定的对照动作，不能偷偷混入原生测试。

## 接口约定（以下新增项均为拟议接口）

### 日常动作与客户端

保持 `POST /action` 和步骤结构。现有调用不必改变：

```python
act([{"op": "click_at", "x": 248, "y": 540}], "result.jpg")
```

- 首版仍使用完整496×1080竖屏截图像素；`x=0..495,y=0..1079`。不同时引入0..1000归一化公共接口，以免混淆现有调用。
- `move` / `tap` 的dx/dy仍是相对HID单位；不改名、不改单位。`drag` / `scroll` / 键盘不在本轮改写范围。
- Action新增可选 `coordinate_backend: native_hid | visual_relative`，缺省使用服务配置。迁移初期默认仍为旧后端，验收完成后才切换默认；health及每条结果必须返回实际选择。
- 新增客户端包装 `move_to(x,y,output,...)`、`click_at(x,y,output,...)`，内部仍调用act，不创建串口会话。act增加可选backend和capture参数，原默认值保持不变。
- 客户端新增health、start_calibration、get_calibration、cancel_calibration方法；CLI保留原有steps用法，新增操作不能破坏现有调用。
- 请求发送前仍保存request_id；原生命令结果未知时不自动重发，不能因截图失败改换视觉/相对后端再点一次。

原生坐标链：完整截图目标 → 可选逆映射修正 → HID整数范围0..32767 → 固件。没有修正时直接使用 `round(x/495*32767)`、`round(y/1079*32767)`。修正后越界应拒绝，不能静默裁剪到边缘。

“页面CSS → 完整截图”的变换只用于校准测量，与“完整截图 → HID”的运行变换分开保存。不能把校准页的内容区域比例用于其他App的全屏坐标。

### 状态与结果语义

GET /health增加：实际后端、固件能力、absolute_ready、屏幕几何状态、配置ID/验证状态/范围、当前校准任务。不要将缓存的status或上次命令坐标当成手机实时位置。

保留action/input_state、release、capture、completed_steps、request_id、instance_id及现有absolute字段。为absolute条目增加backend、profile_id、目标像素、实际提交的HID坐标、报告数和验证信息。

- 原生move成功只表示report_submitted，不能返回视觉后端的reached来暗示已看到指针到位。
- 原生click成功表示click_submitted；业务是否命中仍由最终截图/页面结果验收。
- 修改execute对不同后端的成功判断，不能简单复用目前只接受reached/click_submitted的判断。
- 完整请求预检发现能力/配置/几何不满足时，零输入返回not_started和明确原因。已开始执行后发生故障才用partial_unknown。
- 去重同ID返回原结果和原图，不重新输入、不重新校准；新观察必须新ID。后端及配置版本应进入执行记录，配置更新不可改变已排队任务的含义。

### 校准任务

拟新增：

| 接口 | 语义 |
|---|---|
| `POST /calibrations` | 提交唯一request_id、mode=`verify`或`calibrate`；返回202、job_id和校准页地址 |
| `GET /calibrations/{job_id}` | 阶段、样本、失败原因、最终配置及证据位置 |
| `POST /calibrations/{job_id}/cancel` | 请求取消并释放输入，不自动重启任务 |

先创建任务/页面会话，操作者打开页面，服务确认四标记、视口和页面ready后再进入采样。打开页面与采样分别计时。不要把“打开网页也完全自动”列为首版校准算法前提；客户端应明确提示当前等待页面还是正在执行。

状态顺序：waiting_for_page → sampling → fitting（calibrate模式）→ validating → passed / failed / cancelled。任务有整体截止时间，等待页面也有上限。使用异步job，不把长任务塞进现有/action的45秒上限；创建接口返回后断开HTTP不等同取消任务，须通过job接口取消。提交超时以同request_id查询/去重，不创建第二个任务。

## 回退与交付边界

视觉后端通过显式配置/请求选择，原生动作发生partial_unknown后不得在同一请求里自动回退并重复点击。缺能力的旧固件应返回unsupported，而不是模拟“原生成功”。

若需回退固件，先停串口服务、核验板子与备份，再按实验恢复说明操作；描述符/配对和配置验证状态一并检查。整个流程保持UxPlay/取帧服务运行。

交付应包括正式源码、客户端用法、校准配置/事件契约、相关自动化测试及主代理验收报告。当前没有需要先向用户再次确认的架构决策；页面事件关联、有效范围及输入法稳定性属于实施时必须解决的工程项。写完本计划不代表上述实现已完成。
